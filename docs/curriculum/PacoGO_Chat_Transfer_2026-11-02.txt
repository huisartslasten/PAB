============================================================
1. WAAR WE ZIJN
============================================================

PacoGO Curriculum is niet meer alleen een curriculumdocumentatieproject. De wetenschappelijke/curriculumlaag, de generieke learning engine en de eerste empirische validatie-infrastructuur bestaan inmiddels als samenhangend prototype.

De cruciale volgende stap is nu de brug naar echte leerlinginteractie.

De centrale architectuur is:

CURRICULUM
→ SKILL
→ DEVELOPMENT
→ CLAIM
→ EVIDENCE TARGET
→ TASK MODEL
→ TASK INSTANCE
→ INTERACTION
→ OBSERVATION
→ EVIDENCE
→ DEVELOPMENT INFERENCE
→ MASTERY
→ DECISION
→ NEXT ACTION

De huidige technische focus is de eerste volledige verticale slice:

A1 GETALLEN REPRESENTEREN EN VERBINDEN
→ GETALLENLIJN
→ BROWSERINTERACTIE
→ OBSERVATIE
→ ENGINE

Dit is bewust gedaan voordat we tientallen afzonderlijke skill-apps gaan bouwen.

============================================================
2. BELANGRIJKSTE BESLISSING VAN DEZE FASE
============================================================

We gaan NIET voor iedere skill een aparte technische mini-app bouwen.

We bouwen eerst een herbruikbare interaction architecture.

Voorbeelden van toekomstige interaction families:
- SELECT
- MATCH
- SORT
- ORDER
- LABEL
- DRAG
- PLACE_ON_AXIS
- MOVE_MARKER
- DRAW
- RESIZE
- SPLIT
- COMBINE
- GROUP
- ROTATE
- REARRANGE
- SET_TIME
- MOVE_HAND
- SEQUENCE_EVENTS
- SET_DURATION
- TYPE_VALUE
- SELECT_SYMBOL
- COMPLETE_EXPRESSION

De getallenlijn is de eerste concrete implementatie omdat die inhoudelijk goed past bij A1 en technisch een goede test is van de architectuur.

Belangrijk:
interaction complexity ≠ development
interaction data ≠ automatisch evidence
correct antwoord ≠ automatisch mastery

7. EXACTE VOLGENDE STAP
============================================================

De volgende ChatGPT-sessie moet NIET opnieuw beginnen met curriculumtheorie.

DOE IN DEZE VOLGORDE:

STAP 1 — CI FAILURE ISOLEREN
- controleer de laatste workflow run op branch refactor/professional-v1;
- lees de output van "Run curriculum engine regression";
- bepaal exact welke test faalt en waarom;
- repareer alleen de echte oorzaak;
- voeg indien nodig een gerichte regression test toe;
- voer opnieuw volledige regressie uit.

STAP 2 — BROWSER VERTICAL SLICE GROEN MAKEN
Pas als de curriculum-engine tests groen zijn:
- browser test laten draaien;
- controleren dat de browser daadwerkelijk een observation produceert;
- controleren dat observation_id behouden blijft;
- controleren dat curriculum_registry_version behouden blijft;
- controleren dat evidence wordt opgebouwd;
- controleren dat mastery NIET uit één correcte observatie naar MASTERED springt;
- controleren dat decision/next action wordt geproduceerd.

STAP 3 — VERTICAL SLICE ALS ARCHITECTUURTEST BESCHOUWEN
De eerste echte keten moet aantoonbaar werken:

curriculum
→ task model
→ task instance
→ browser interaction
→ interaction events
→ observation
→ evidence
→ inference
→ mastery
→ decision
→ next action

STAP 4 — PAS DAARNA HERBRUIKBAARHEID TESTEN
Daarna niet meteen tientallen skills bouwen.
Bouw een tweede domein, bij voorkeur FR2/breuken, met zoveel mogelijk dezelfde interaction architecture.

Waarom breuken?
Omdat hiermee getest wordt of de architecture echt generiek is en niet stiekem alleen een getallenlijn-engine is.

STAP 5 — DAARNA VERDER
Pas nadat A1 + tweede domein technisch werken:
- interaction families verder abstraheren;
- browser event collector verder generaliseren;
- observation adapters generaliseren;
- daarna pas meer skills aansluiten.
