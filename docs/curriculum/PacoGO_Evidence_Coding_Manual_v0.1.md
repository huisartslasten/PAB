# PacoGO Evidence Coding Manual v0.1

Date: 2026-11-02  
Status: Candidate protocol / [O]  
Scope: C3 evidence coding for A1, B1 and FR2 pilot observations.

## 1. Core rule

Code what is **observable**, not what the coder thinks the learner's developmental level is.

The coding chain is:

`performance → observation → evidence target → evidence assessment → later inference`

Never:

`correct answer → development → mastery`

## 2. Evidence status

### PRESENT
The observation contains the information required by the evidence target and the target is supported by the observed response/process.

### ABSENT
The required evidence was available to inspect, but the target evidence was not demonstrated.

### INDETERMINATE
The available observation cannot distinguish support from non-support.

### NOT CODED
Coding has not yet been performed. This is different from ABSENT.

## 3. Evidence-target match

### MATCH
The observation genuinely provides information about the specified evidence target.

### MISMATCH
The task/response does not test the target despite being associated with it in the registry.

### UNCLEAR
The relationship cannot be determined from the available information.

A mismatch is a task-design finding, not automatically a learner failure.

## 4. Quality

Quality is an evidence-quality field, not a learner ability score.

The initial coding scale is:

- `1.0` = clear, direct, interpretable evidence;
- `0.5` = partially interpretable or limited evidence;
- `0.0` = no interpretable evidence for the target.

These values are provisional coding conventions `[O]` and must not be treated as validated measurement cut scores.

## 5. Independence

### INDEPENDENT
The learner produced the relevant response/process without assistance that supplied the target reasoning.

### PROMPTED
A prompt materially supported the target response.

### DEPENDENT
The response depended on direct assistance or information that prevents interpretation of independent evidence.

### UNKNOWN
The observation does not contain enough information to classify independence.

## 6. Contradiction

Set `contradiction=true` only when the observation contains evidence that directly conflicts with an inference that would otherwise be drawn from the same claim/evidence target.

Examples:

- correct answer + demonstrably incompatible reasoning for a reasoning-dependent target;
- success in one representation + failure on a pre-specified equivalent variation;
- claimed independent performance + evidence of direct prompting.

A simple wrong answer is not automatically a contradiction. It may simply be absence of support.

## 7. Alternative explanations

Record a plausible alternative explanation when the observed result could reasonably arise without the intended construct being present.

Common pilot categories:

- memorization;
- item familiarity;
- language comprehension;
- prompting;
- representation-specific strategy;
- general task familiarity;
- cueing;
- calculation/notation error unrelated to the target construct.

Alternative explanations are hypotheses to test, not diagnoses.

## 8. A1 coding examples

### A1.C1 — representational meaning
Code PRESENT when the learner's response demonstrates identification of the intended number/quantity relation.

Do not infer A1.D1 merely because the final label is correct if the task permits a superficial cue.

### A1.C2 — mapping
Code PRESENT when the learner correctly maps equivalent numerical value across representations.

For changed representations, record the variation key so stability can later be examined.

### A1.C3 — coordination
Require evidence that multiple representations are coordinated, not merely that each representation can be answered separately.

## 9. B1 coding examples

### B1.C1 — part-whole relation
Code the observed representation of quantities and total, not just the numerical answer.

### B1.C2 — executing addition
Correct execution may support the execution target, but does not alone establish strategic or flexible development.

### B1.C3 — strategy and checking
Code the selected approach and whether checking is actually demonstrated.

### B1.C4 — robust addition
Look for the same underlying addition relation under pre-specified variation.

## 10. FR2 coding examples

### FR2.C1 — recognize equivalence
Code whether the learner distinguishes equivalent from non-equivalent fractions.

### FR2.C2 — explain equivalence
The explanation/representation must provide evidence for same-value reasoning. A correct pair selection without such evidence remains insufficient for this target.

### FR2.C3 — functional use
Code whether the learner independently uses equivalence to support another mathematical purpose when the task permits this inference.

## 11. Double-coding and disagreements

For judgment-dependent observations:

1. two coders independently apply the frozen codebook;
2. original codes are retained;
3. disagreement is recorded before discussion;
4. resolution follows the predefined adjudication rule;
5. the adjudicated code is stored separately from the original codes.

Agreement is evidence about coding reproducibility, not evidence that the underlying developmental model is true.

## 12. Coding changes

If the codebook changes after observations have been coded:

- create a new codebook version;
- do not silently overwrite the historical coding;
- record which observations were recoded;
- record why the rule changed;
- preserve the prior result.

## 13. Scientific boundary

This manual establishes a reproducible observation/evidence coding procedure. It does not establish:

- developmental stages;
- developmental ordering;
- mastery thresholds;
- causal learning mechanisms;
- curriculum effectiveness.

Those require later empirical validation under C4-C10.
