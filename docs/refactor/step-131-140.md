# PacoGO Professional Refactor — Checkpoint 131–140

Baseline: PacoGO TEST V4.78
Reference branch: `backup-test-v478-before-professional-rewrite`
Work branch: `refactor/professional-v1`

## 131 — Authorization source verified

The V4.78 lesson-management boundary was checked against the legacy source. The mutation entry point `saveLesson()` starts with `requireParent()`. The corresponding V4.78 helper allows only a logged-in parent session. The same parent guard is also used by the test-calendar mutation actions visible in the same source area.

The refactor already has the equivalent role state in `src/core/auth.js`.

## 132 — Mutation service boundary reviewed

`src/services/lesson-service.js` already contains the isolated data mutations for:

- create lesson
- update lesson
- replace lesson items
- archive
- move to trash
- restore

The service deliberately remains authorization-agnostic: it is a data boundary, not a UI role boundary.

## 133 — Lesson-management boundary added

Added:

`src/features/lessons/lesson-management.js`

This is the first orchestration boundary above the data service. It enforces the verified parent-only rule before any mutation reaches the service.

The boundary currently exposes:

- `create({ lesson, items })`
- `update(id, { lesson, items })`
- `archive(id)`
- `moveToTrash(id)`
- `restore(id)`

Runtime wiring is intentionally deferred.

## 134 — Mutation order made explicit

Create/update orchestration is explicit:

1. mutate the lesson row;
2. replace its lesson items;
3. return the lesson row returned by the lesson mutation.

This does not claim transactional behavior. The purpose of this checkpoint is to make the current application-level mutation sequence explicit before any runtime migration.

## 135 — Authorization regression tests added

Added `test/lesson-management.test.js` covering:

- non-parent sessions cannot create, update, archive, trash, or restore;
- authorization failure happens before the service is called;
- create calls lesson creation before item replacement;
- update calls lesson update before item replacement;
- archive/trash/restore remain parent-only.

## 136–140 — Gate status

The new boundary is additive and not mounted into the legacy runtime.

No Supabase schema changes were made.

No `main`/LIVE branch changes were made.

The V4.78 backup remains read-only.

### Important unresolved parity items

The exact field-building logic inside the legacy editor save/update flow still needs to be reconstructed before the new management boundary can be considered a full editor parity replacement. In particular, the next pass must verify:

- exact lesson payload fields;
- exact lesson-item payload fields and normalization;
- create vs update differences;
- edit/delete behavior for existing lesson items;
- validation and error messages;
- any ordering/subvak/metadata fields written during save;
- whether any mutation has additional role or ownership checks beyond the verified parent guard.

Therefore this checkpoint does **not** authorize runtime wiring yet.
