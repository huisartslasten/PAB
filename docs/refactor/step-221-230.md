## V4.78 result parity
The result flow was checked against the available V4.78 source material before changing the isolated result model.

Verified V4.78 test-result behavior:
- The result page is separate from the test page.
- Dictation uses the title `✏️ Dictee klaar!`.
- Other word-test results use `📝 Toets klaar!`.
- The score is displayed as a grade on a 1.0–10.0 scale.
- The grade is calculated as `correct / total * 10` and rounded to one decimal.
- The result shows `correct van total goed`.
- Each answer is reviewed with the learner's entered answer and, when incorrect, the expected answer.
- The result page offers `Nog een keer`, which returns to the lesson-choice view.
- The result page offers `Terug naar les`, which follows the normal lesson back navigation.

## Extracted player runtime boundary
A deterministic adapter now exists at:
- `src/features/lessons/player-runtime-adapter.js`

It is additive and remains unmounted. It is the single composition point for:

`player-session → player-attempt → finish-flow → result + persistence → navigation callbacks`

The adapter:
- starts the typed test session;
- creates the explicit attempt contract;
- maps the player model to the existing snake_case persistence contract;
- invokes the finish flow;
- injects result rendering, speech cancellation and activity cleanup;
- preserves the two V4.78 result actions through `retry()` and `back()` callbacks.

It contains no DOM implementation, no Supabase implementation and no direct navigation implementation.

## Persistence contract
The adapter maps the completed test to the established persistence-model fields:
- `test_attempts`: `lesson_id`, `student`, `score`, `total_questions`, `started_at`, `completed_at`, `is_test`;
- `test_attempt_answers`: `question_order`, `question`, `expected_answer`, `given_answer`, `is_correct`, `question_type`.

The adapter does not add camelCase player fields to database rows.
