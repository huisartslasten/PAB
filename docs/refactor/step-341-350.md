## 341–347 — Editor item ordering parity

The extracted editor item builder was compared with the already reconstructed V4.78 `collectItems()` contract.

A parity difference was found in `src/features/lessons/editor-items.js`:

- the V4.78 collector assigns `sort_order` from the original editor-row index;
- the extracted builder previously re-indexed only the accepted items after invalid rows had been removed.

That could change persisted ordering when an earlier editor row was incomplete and therefore omitted.

### Correction
`buildItemsForType()` now assigns `sort_order` before filtering omitted rows, preserving the original source-row index.

Example:
- row 0 invalid → omitted
- row 1 valid → `sort_order: 1`
- row 2 valid → `sort_order: 2`

This matches the reconstructed V4.78 collector behavior.
