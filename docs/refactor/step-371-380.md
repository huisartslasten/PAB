## Exact V4.78 save flow

`saveLesson()` performs these steps, in this order:

1. Require parent authentication.
2. Read editor state from the DOM:
   - student
   - subject
   - title
   - explanation
   - lesson type
   - entered subvak
   - AI answer-check setting
   - AI instruction
   - spelling editor labels when type is spelling
   - optional test date
3. Resolve the subvak spelling from an existing lesson when student, subject, and normalized subvak match. Otherwise use the entered subvak.
4. Call `collectItems()`.
5. Reject the save when student, subject, title, or item collection is missing/empty with:
   `Vul het vak, de lestitel en minstens één item in.`
6. For dictation only, run the AI spelling check. Warnings do not block saving; AI failure also does not block saving.
7. Update an existing lesson first, or create a new lesson first.
8. For an update, delete existing `lesson_items` and then insert the collected items.
9. For a create, insert the new `lesson_items` after the new lesson id exists.
10. On persistence error, show `Opslaan mislukt: ...` and stop.
11. On success, set `currentSubject`, clear `currentLesson`, reload lessons, and locate the saved lesson.
12. Add/update/remove the local test-calendar entry according to the optional test date.
13. Refresh the test calendar and page sidebars.
14. Show a success message; when a test date exists the message is:
    `Les opgeslagen en toetsdatum toegevoegd.`
    Otherwise:
    `Les opgeslagen.`

## Refactor mapping

Already isolated:

- `lesson-item-collector.js` — editor item collection.
- `lesson-save-validation.js` — pre-persistence required-field validation.
- `lesson-write-service.js` — deterministic lesson + item persistence ordering.
- `lesson-save-model.js` — lesson-level save payload, item normalization, test-date handoff.
- `lesson-service.js` — direct Supabase lesson persistence boundary.

Still deliberately outside the write service:

- parent-auth guard
- DOM/editor extraction
- dictation AI spelling check
- test-calendar side effect
- lesson reload
- sidebar/calendar rendering
- success/error UI
- navigation/state changes

These are orchestration concerns and must not be silently added to the persistence service.

## Important parity detail

The legacy function canonicalizes an entered subvak by finding an existing lesson with the same student, subject, and normalized subvak. The resulting existing spelling is reused. The extracted model accepts the already-resolved `existingSubvak`; the DOM lookup itself remains outside the pure model.
