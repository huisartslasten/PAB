## Source-proven V4.78 contract
After a successful lesson persistence operation, V4.78 performs the following post-save sequence:

1. Set `currentSubject = subject`.
2. Set `currentLesson = null`.
3. `await loadLessons()`.
4. Find the saved lesson again by numeric id.
5. Only when that saved lesson is found, perform the previously isolated test-calendar action:
   - truthy `testDate` → upsert;
   - empty `testDate` → remove.
6. Render the test calendar.
7. Refresh page sidebars.
8. Show the success message selected from `testDate`.

Important parity detail: V4.78 does **not** assign the reloaded `savedLesson` to `currentLesson`; `currentLesson` remains `null` in this flow.

If the reloaded lesson cannot be found, V4.78 skips the calendar mutation but still proceeds to calendar rendering, sidebar refresh, and the success message.

The exact success messages are:

- with `testDate`: `Les opgeslagen en toetsdatum toegevoegd.`
- without `testDate`: `Les opgeslagen.`
