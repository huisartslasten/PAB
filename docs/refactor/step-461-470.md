## Boundary added
`src/features/lessons/lesson-save-request.js`

`buildLessonSaveExecutionRequest(model)` now explicitly preserves the handoff:

`lesson-save-adapter → lesson-save-model → lesson-save-request → lesson-save-coordinator → lesson-write-service`

The request preserves:
- existing lesson id or `null` for create;
- canonical lesson payload;
- item payload and `sort_order`/other item fields;
- test date for the post-persistence calendar contract.

The item array is copied so the execution boundary cannot mutate the canonical model's item objects.

## Why this boundary exists
The coordinator currently accepts separate `id`, `lesson`, `items`, and `testDate` concepts through its injected contracts. Keeping that translation explicit prevents the runtime call site from becoming the place where payload shape, persistence semantics, and UI/state behavior are mixed together.
