# PacoGO refactor — checkpoint 511–520

## Scope
Controlled TEST runtime wiring for the V4.78 lesson-save flow.

## What was verified from source
- `index.html` on `refactor/professional-v1` is still the authoritative V4.78 blob `de4ebcc75b1b333cc985936c86f7c654c818be24`.
- The legacy page is a classic script environment.
- `photo-storage.js` is also a classic script and already reads the V4.78 lexical application bindings directly.

## Change
The runtime boundary was corrected so the ES module receives an explicit V4.78 runtime bridge from the classic-script boundary.

`photo-storage.js` now builds a bridge with live getters/setters for:
- `document`
- `db`
- `currentSubject`
- `currentLesson`
- `currentSession`
- `PARENT_IDS`
- `lessons`
- `currentStudent`
- `normalizeSubvakKey`
- `renderTestCalendar`
- `refreshPageSidebars`
- `showMessage`
- `showHome`
- `loadLessons`
- `checkDictationSpelling`
- `upsertTestDate`
- `removeTestDate`

The module entry now requires that bridge explicitly and no longer resolves those names from ES-module scope.

## Test coverage
`test/lesson-save-runtime-entry.test.js` now verifies:
1. the runtime entry replaces `window.saveLesson` and returns the legacy function;
2. rollback reference preservation;
3. direct execution without the explicit bridge is rejected.

A temporary GitHub Actions workflow was created to run `npm test` on this TEST branch, but GitHub reported no workflow run for the branch, so no CI result is claimed. The temporary workflow was removed again.
