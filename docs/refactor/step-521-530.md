# PacoGO Refactor — Checkpoint 521–530

## Scope
Harden the controlled V4.78 lesson-save runtime boundary after the 511–520 ES-module/classic-script bootstrap seam.

## Architectural finding
The controlled runtime entry was resolving an editor-error DOM element and constructing the lesson write service before the authorization boundary. That was an architectural ordering defect. It was not patched in legacy code.

The corrected boundary is:

`facade → bootstrap → explicit bridge → authorization → editor read/preparation → coordinator dependencies → persistence/effects`

## Changes

### Runtime effects
The runtime-effects boundary resolves the editor-error element lazily at execution time instead of requiring an eagerly resolved DOM element during construction.

### Runtime entry
The runtime entry now defers the lesson write-service construction until coordinator execution. Authorization remains the first executable application step. The ES-module continues to receive all classic-script application dependencies through the explicit V4.78 bridge.

### Editor item parity
The editor item conversion boundary was corrected so an omitted `answer_parts` value can use the V4.78 legacy `answer` fallback. An explicitly supplied empty parts array remains distinct.

### Save request contract
The canonical save-request boundary now rejects a missing save model rather than silently coercing the absence to an empty object.

### Regression coverage
The bootstrap readiness assertion was tightened to prove ordered module loading and exactly-once installation. Runtime-effects coverage proves lazy DOM lookup and outcome-driven completion.
