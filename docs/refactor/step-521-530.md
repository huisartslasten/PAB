# PacoGO Refactor — Checkpoint 521–530

## Scope
Harden the controlled V4.78 lesson-save runtime boundary after the 511–520 module/bootstrap seam was established.

## Source / architecture finding
The runtime entry was doing two application-side lookups before parent authorization:
- resolving `#editorError` from the DOM;
- constructing the lesson write service from the live database bridge.

That violated the intended authorization-first runtime contract. The correct architectural responsibility is to resolve those dependencies only when the authorized save path reaches the corresponding execution boundary.

## Changes

### 1. Runtime effects now resolve the editor-error DOM dependency lazily
`lesson-save-runtime-effects.js` now accepts `getErrorElement()` instead of an eagerly resolved DOM element.

Validation/persistence handlers resolve the element at execution time. Construction of the effects adapter is therefore DOM-independent.

### 2. Runtime entry now defers DOM and DB access
`lesson-save-runtime-entry.js` now:
- creates a lazy `getErrorElement()` resolver;
- constructs the lesson write service inside the coordinator execution boundary, after authorization/read/prepare have succeeded;
- keeps authorization as the first executable application step;
- preserves the existing V4.78 coordinator ordering and application effects.

No legacy `index.html` patch was used.

### 3. Editor-item fallback parity corrected
`editor-items.js` had a default parameter that converted an omitted `answer_parts` field into an empty array before the legacy `answer` fallback could run. This caused valid legacy-shaped rows to disappear.

The boundary now distinguishes an omitted `answer_parts` value from an actual empty array, restoring the intended V4.78 fallback behavior.

### 4. Save-request input contract tightened
`lesson-save-request.js` no longer defaults a missing model to `{}`. A missing save model now deterministically fails the declared contract.

### 5. Bootstrap regression assertion corrected
`lesson-save-runtime-bootstrap.test.js` now asserts the actual ordered event contract: module load followed by exactly one installation event.

### 6. Write-service test contract clarified
The lesson-write-service test now explicitly includes the `lesson_items` table boundary before its insert operation. This matches the service's actual Supabase boundary behavior. This standalone test was not part of the executed 70-test gate described below.
