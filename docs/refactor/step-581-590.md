# PacoGO Refactor — Checkpoint 581–590

## Boundary
Photo-to-lesson creation (`createLessonFromPhoto`) was migrated from the V4.78 monolith into the refactored lesson runtime.

## V4.78 behavior preserved
The boundary preserves the authoritative photo lesson creation contract for:
- parent authorization as a hard stop;
- deterministic lesson creation followed by lesson-item persistence;
- rollback of the created lesson when item persistence fails;
- lesson reload before application state is restored;
- restoring the created lesson's student, subject, and current-lesson state;
- source-photo persistence through the existing photo-storage boundary when available;
- exact success message: `Les gemaakt uit de foto. Controleer hem gerust nog even.`;
- success message before dashboard navigation;
- persistence failure stopping before the success/dashboard effects.

## Architecture
The boundary is split into:
- `src/features/lessons/lesson-photo-runtime.js` — pure photo-to-lesson orchestration and behavior contract;
- `src/features/lessons/lesson-photo-write-service.js` — deterministic lesson/item persistence and rollback;
- `src/features/lessons/lesson-photo-runtime-entry.js` — classic-script bridge adapter and runtime contract validation;
- `src/features/lessons/lesson-photo-runtime-bootstrap.js` — explicit dynamic bootstrap/readiness boundary;
- `photo-storage.js` — live V4.78 bridge and synchronous public `window.createLessonFromPhoto` facade.

## Legacy removal
The legacy V4.78 `async function createLessonFromPhoto()` implementation was removed from `index.html` only after the replacement boundary had focused tests and the controlled browser fixture had been aligned with the actual runtime contract.

The one-time removal workflow verified the expected legacy function boundaries and exact V4.78 persistence/success-message markers before deleting the implementation. It then verified that no legacy declaration remained and deleted itself immediately afterward.

## Source contract
`test/lesson-photo-runtime-source-contract.test.js` guards both sides of the boundary:
- `index.html` must not regain a legacy `createLessonFromPhoto` declaration;
- `photo-storage.js` must retain the single photo bootstrap/readiness facade without a legacy fallback or duplicate bootstrap.
