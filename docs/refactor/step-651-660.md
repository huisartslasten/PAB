# PacoGO refactor — steps 651–660

## Scope
Player architecture cleanup after the application-facing runtime entry was proven structurally.

## Source contract
Authoritative V4.78 behavior remains the baseline from blob `de4ebcc75b1b333cc985936c86f7c654c818be24`:

- `startTest()` creates the test session and renders the first item.
- `submitTest()` reads the exact DOM controls, delegates grading, advances the session, renders the next item, and calls `finishTest()` on the final answer.
- `finishTest()` persists history, renders the result, and clears activity.

## Architecture decision
The earlier `player-runtime.js` / `player-runtime-bootstrap.js` pair represented a second runtime concept that was narrower than, and separate from, the application-facing player composition now used by `player-runtime-entry.js`.

Those superseded files and their dedicated tests were removed from `refactor/professional-v1` rather than retained as compatibility layers.

The intended player architecture is now:

```text
application context
      ↓
player-runtime-entry
      ↓
player-runtime-composition
      ↓
player-runtime-adapter
      ↓
player-submit-boundary
      ↓
test-engine
      ↓
player-attempt / finish-flow / persistence / result
```

This is an architectural cleanup, not a legacy patch. No `index.html` player implementation was changed.
